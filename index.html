Core Capabilities

Four towers, one platform

Every pillar instruments a different layer of your data platform and feeds signals into a single Elastic + Kibana surface.

Data Freshness

Track last-updated timestamps across S3, Glue, Athena, RDS and more. Get alerted the moment a table goes stale beyond its SLO threshold.

Data Quality

Row count checks, null rate, uniqueness, schema drift, and custom SQL assertions — all emitted as OTel metrics into Elastic for real-time dashboards and alerting.

Data Lineage

Automatically graph how data moves across Lambda, Glue, EMR, S3 and RDS. Instantly surface downstream impact when a source changes or fails.

Infrastructure Observability

EC2, EKS, Lambda, and EMR metrics, logs and traces — collected via OTel Collector and shipped to Elasticsearch alongside your data quality signals.

How it works

Up and running in four steps

DataObs is deployed as containers alongside your existing AWS stack — no SaaS, no lock-in.

Deploy the stack

Run docker-compose up or apply the Helm chart to your EKS cluster. Elasticsearch, Kibana and the OTel Collector start automatically.

Point at your AWS resources

Drop a single YAML config listing your S3 buckets, Glue databases, RDS tables and Lambda functions. DataObs handles the rest.

Define your SLOs

Set freshness windows, row count baselines and quality thresholds per dataset. Violations fire as Elastic alerts to Slack, PagerDuty or email.

See everything in Kibana

Pre-built dashboards show freshness heat-maps, quality trends, lineage graphs and infra metrics — side by side in one pane of glass.
